# 大会使用ボール登録システム・ロードマップ（2026-07-30）

## 目的

紙で行っているボール名・シリアルナンバー・使用大会の登録をデジタル化する。
選手本人がスマートフォン等から登録でき、スタッフによる代理入力・承認も可能にする。
大会速報・成績ページの選手情報から、その大会で承認済みの使用ボールを閲覧できるようにする。

## 確定要件

- 選手本人がログインして登録する。
- 年配選手等のため、スタッフは選手を指定して代理入力できる。
- 同一モデルが約100人の異なる選手から選ばれることを想定する。1選手が同一モデルを2～3個所有する場合は、現物ごとに別のシリアルナンバーで登録できる。
- シリアルナンバーの大量一括入力機能は作らず、選手が所有する現物を1件ずつ分かりやすく登録する。
- 大会ごとの登録可能個数は、大会要項作成時に設定する。
- 選手ボールの年度登録は暦年単位で有効とする。同年度内なら登録月を問わず有効で、翌年は再登録・再承認する。
- スタッフ承認を必須にする。
- 過去に登録した現物ボールはマイボールリストへ残し、次回以降再利用できる。
- マイボールリストの削除は物理削除ではなく使用停止とし、過去大会履歴は保持する。
- 全メーカーボールを写真付きでカタログ化する。写真がない場合は共通のNo Imageを表示する。
- メーカー別に分類し、読み仮名を持たせて五十音順に表示する。
- メーカーサイトからボール情報・写真を自動収集する。
- 毎月増える新製品を、指示1回で差分取得・候補作成できるようにする。
- 自動取得結果は重複排除し、メーカーサイト掲載品はカタログへ登録する。JPBA大会で選べるかどうかは、後から共有されるアブプールリストで別途設定する。
- スタッフ承認は、選手がその年度に申請したボールを選手単位で一括承認する。
- 将来実装する検量証は、年度登録とは分離し、登録日から1年間有効とする。

## 既存システム調査

- `approved_balls`
  - 公認ボールマスターの土台。名称、読み、メーカー、発売日、公認状態を保持できる。
  - 現在0件。画像・メーカー正規化・取得元・差分取込情報は未実装。
- `used_balls`
  - 選手が所有する現物ボールの土台。選手、ボールモデル、シリアル、検量証情報を保持する。
  - 現在0件。マイボールリストとして再構成する。
- `approved_ball_pro_bowler`
  - 年度単位のモデル紐付けはあるが、シリアル単位・承認状態を持てない。
  - 現物ボール単位の年度申請・承認テーブルへ置き換える。
- `registered_balls`
  - 検量証番号・登録日・有効期限を保持する既存土台。
  - 年度登録と混在させず、後続の検量証機能で整理する。
- `tournament_entry_balls`
  - 大会エントリーと選手の現物ボールを紐付ける既存土台。
  - 速報・成績ページ連携の正本として継続利用する。
- `tournaments`
  - `inspection_required` はあるが、大会別ボール上限は未実装。
  - 現在の大会使用ボール上限12個はControllerへ固定値で書かれているため、大会設定へ移す。
- 認証
  - 会員・編集者・管理者のロールと `users.pro_bowler_id` の接続口は実装済み。
  - 実DBは管理者1アカウントのみで、選手アカウントは0件。選手本人ログインの発行・初期設定が必要。

## データの役割分担

1. ボールカタログ
   - メーカー、ブランド、モデル名、読み、発売日、写真、商品URL、公認状態、販売終了状態を管理する。
2. マイボールリスト
   - 選手が実際に所有する現物を、カタログモデル＋シリアルナンバーで管理する。
   - 同じモデルを何個でも登録できる。
3. 年度登録・スタッフ承認
   - 現物ボールごとに年度、申請状態、承認者、承認日時、差戻し理由を保持する。
4. 大会別使用ボール
   - 承認済み年度登録の中から、大会上限以内で選択し `tournament_entry_balls` へ紐付ける。
5. 検量証
   - 現物ボールごとに検量証番号、登録日、1年後の有効期限を別管理する。

## 実装順序

### 第1段階：カタログ基盤

- メーカーマスターを追加する。
- `approved_balls` を写真・取得元・読み順・公開状態・差分取込に対応させる。
- 写真なし共通画像を用意する。
- 管理画面でメーカー別・五十音順・検索・写真確認・編集を可能にする。
- 取込候補と取込実行履歴を保持し、途中停止・再開・重複防止を実装する。

### 第2段階：全メーカー自動収集

- 対象メーカーごとに公式サイト取得アダプターを作る。
- ボール名、読み、発売日、商品URL、写真URLを取得する。
- 画像は外部直リンクではなくローカル保存し、取得元URLを管理用に保持する。
- 全件バックフィルを低速・再開可能なバックグラウンド処理で実行する。
- メーカー別件数、写真取得率、重複候補、取得失敗を監査する。

### 第3段階：毎月の差分更新

- 「全メーカー新製品確認」を1回の指示・コマンドで実行できるようにする。
- 前回取得以後の追加・変更だけを候補化する。
- スタッフ確認後に公開する。
- 実行日、対象メーカー、追加件数、更新件数、要確認件数、エラーを履歴保存する。

### 第4段階：選手ログインとマイボール

- 選手アカウントを `pro_bowlers` と一対一で結線する。
- 初回ログイン・パスワード再設定・スタッフ代理入力を整備する。
- メーカー別・五十音順・写真付きカタログからモデルを選択する。
- 同一モデルを2～3個所有する場合も、シリアル番号の異なる現物として1件ずつ登録する。
- 追加、編集、使用停止、再有効化を実装する。

### 第5段階：年度申請とスタッフ承認

- 年度ごとの申請、下書き、提出済み、承認済み、差戻しを実装する。
- 同年度内は承認済み状態を再利用し、翌年度は再申請する。
- スタッフが選手を指定し、その選手の年度申請をまとめて承認できるようにする。
- 代理申請と承認操作の監査履歴を実装する。

### 第6段階：大会別登録

- 大会要項作成画面へボール登録上限を追加する。
- Controller固定の12個上限を大会設定値へ置き換える。
- 該当年度の承認済みマイボールだけを大会選択候補にする。
- 大会別の追加・入れ替え・解除を実装する。
- 過去大会履歴を壊さないため、マイボールは物理削除しない。

### 第7段階：速報・成績ページ連携

- `tournament_entries` → `tournament_entry_balls` → `used_balls` → `approved_balls` のID接続を利用する。
- 速報・大会成績ページの選手クリック時に、その大会の登録ボール名・メーカー・シリアルを表示する。
- 一般公開範囲は速報ページ追加編集時に最終決定する。

### 第8段階：検量証

- 年度登録とは別に、検量日から1年間の有効期限を自動計算する。
- 期限切れ・期限間近・未検量を区別する。
- 大会ごとの検量証必須設定と大会使用可否を連携する。

## 自動収集の安全設計

- 公式メーカーサイトだけを取得元にする。
- メーカーごとに取得間隔・再試行・同時実行数を制限する。
- 取得途中で停止しても未完了メーカー・ページから再開する。
- 同一メーカー＋モデル名＋発売日等のfingerprintで重複を防止する。
- メーカー公式サイトに掲載されている製品はカタログへ登録し、JPBA大会での選択可否は別項目で管理する。
- 画像取得元URLと取得日時を保持する。
- メーカーサイトからの名称・写真転載許可がある前提で、ローカル保存して表示する。
